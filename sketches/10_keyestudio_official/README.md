# Заводская прошивка Keyestudio KS5024

`10_keyestudio_official.ino` — файл `11_4_Video_Car.ino` из официального
репозитория производителя, скопированный без единой правки:

<https://github.com/keyestudio/KS5024-Keyestudio-ESP32-CAM-4WD-Monitoring-Car>

Лежит здесь как эталон: по нему сверены пины моторов, пины камеры, вывод фары
и требование ядра esp32 **2.0.12**.

## Как пользоваться

Вписать свою сеть в строки 18–19:

```cpp
const char *ssid = "your_SSID";
const char *password = "your_PASSWORD";
```

Работает в режиме **STA**: робот подключается к вашей сети или к хотспоту
телефона (2,4 ГГц), а адрес пульта печатается в Serial Monitor на 115200.
Адреса `192.168.4.1` здесь нет — он появляется только в режиме точки доступа,
который добавлен в `03_car_ap_camera`.

## Чем отличается от `03_car_ap_camera`

| | заводская | `03_car_ap_camera` |
|---|---|---|
| Режим Wi-Fi | STA, нужна чужая сеть | AP, сеть раздаёт сам |
| Выбор канала | нет | автоматический, по загруженности эфира |
| Мощность передачи | по умолчанию | принудительно максимальная |
| Стоп при потере связи | **нет** | failsafe через 2 секунды |
| Скорость | три ступени кнопками | ползунок 80–255 |
| Brownout-детектор | **отключён** | оставлен включённым |

Про две последние строки стоит знать отдельно.

**Нет failsafe.** Если закрыть страницу или уйти из зоны на ходу, робот
продолжит ехать до потери питания. В `03` моторы останавливаются через две
секунды без команд.

**Отключён brownout-детектор** — первая же строка `setup()`:

```cpp
WRITE_PERI_REG(RTC_CNTL_BROWN_OUT_REG, 0);
```

Это маскировка, а не решение: при просадке питания плата вместо честной
перезагрузки начинает вести себя непредсказуемо и может испортить содержимое
флеш-памяти. Именно повреждённая калибровка радио во флеш и стоила этому
проекту дня отладки. Если пользуетесь заводской прошивкой — тем более имеет
смысл наладить питание, а не полагаться на выключенный детектор.
