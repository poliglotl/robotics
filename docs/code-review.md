# Ревью исходного скетча

Разбор кода, который вы присылали. Исправленная версия — в
`sketches/02_sta_test/02_sta_test.ino`.

```cpp
#include <WiFi.h>

const char *ssid     = "Car";
const char *password = "test1234";

void setup() {
  Serial.begin(115200);
  ...
  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, password);
  ...
}

void loop() {}
```

## Блокирующие проблемы

### 1. Режим не тот, который вам нужен

`WiFi.mode(WIFI_STA)` — режим клиента. В нём ESP32 **не создаёт сеть** и адреса
`192.168.4.1` у него не появится никогда: этот адрес существует только у
`softAP`. Чтобы робот раздавал Wi-Fi, нужно `WiFi.mode(WIFI_AP)` +
`WiFi.softAP(...)`.

### 2. Плата пытается подключиться к самой себе

`ssid = "Car"`, `password = "test1234"` — это, судя по всему, креды **точки
доступа самого робота**. Плата физически не может подключиться как клиент к
сети, которую раздаёт она же. Даже в правильном STA-режиме тут нужны креды
**вашего роутера**.

Плюс этот скетч затирает заводскую прошивку, которая AP и поднимала — поэтому
сеть `Car` пропала из эфира.

### 3. `loop()` пустой — нет переподключения

Если связь не установилась или отвалилась, плата останется мёртвой до
физического RESET. Для робота это плохо: любая просадка Wi-Fi = потеря
управления навсегда.

## Замечания поменьше

### 4. Нет `WiFi.persistent(false)` и `WiFi.disconnect(true)`

ESP32 по умолчанию сохраняет SSID/пароль в NVS и при старте пытается
подключиться к сохранённому. Это даёт неповторяемые результаты: скетч ведёт себя
по-разному в зависимости от того, что заливали раньше. Лечится:

```cpp
WiFi.persistent(false);
WiFi.mode(WIFI_STA);
WiFi.disconnect(true);
delay(200);
```

### 5. Нет сканирования перед подключением

`FAILED, status code 1` не говорит, в чём дело. Сканирование до `begin()`
отвечает сразу: сеть вообще в эфире или нет. Это и есть ключевая диагностика в
вашей ситуации.

### 6. Статус выводится числом без расшифровки

`WiFi.status()` возвращает:

| Код | Константа | Что значит на практике |
|---|---|---|
| 0 | `WL_IDLE_STATUS` | ещё ничего не делает |
| 1 | `WL_NO_SSID_AVAIL` | **сеть не найдена**: опечатка в SSID, сеть 5 ГГц, далеко, или сети нет |
| 2 | `WL_SCAN_COMPLETED` | сканирование закончено |
| 3 | `WL_CONNECTED` | подключено |
| 4 | `WL_CONNECT_FAILED` | чаще всего **неверный пароль** |
| 5 | `WL_CONNECTION_LOST` | связь была и пропала |
| 6 | `WL_DISCONNECTED` | роутер отбил или подключение ещё не началось |

В вашем случае ожидаемо `1` или `6`.

### 7. Нет `WiFi.setSleep(false)`

По умолчанию STA-режим включает энергосбережение Wi-Fi. Для видеострима и
управления в реальном времени это лишние задержки и рывки.

### 8. Таймаут посчитан в «попытках»

`tries < 40` при `delay(500)` — это 20 секунд, нормально по длине, но считать
лучше по `millis()`: иначе при изменении `delay` таймаут молча меняется.

### 9. ESP32 не видит 5 ГГц

Не про этот код, но про частую ошибку: ESP32 работает **только на 2.4 ГГц**.
Если домашний роутер раздаёт одну сеть с одним именем на обоих диапазонах,
подключение может не получаться. Признак — `status 1` при том, что телефон сеть
видит.

## Что было сделано правильно

- Таймаут с выходом по счётчику, а не `while (status != CONNECTED) {}` навсегда —
  большинство туториалов пишут именно бесконечный цикл.
- `delay(1000)` после `Serial.begin()` — без него первые строки лога на ESP32
  часто теряются.
- Вывод `RSSI` — полезно для диагностики дальности.
- Скетч минимальный и изолированный. Как *диагностика* подход верный, просто
  проверялась не та гипотеза.
