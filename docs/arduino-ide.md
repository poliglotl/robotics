# Arduino IDE 1.8.19 и ядро ESP32: почему так и что выбрать

## Почему код держат в Arduino 1.8.19 (и это не случайно)

Вы спрашивали, откуда взялась именно эта версия. Причина реальная, а не
«исторически сложилось»:

1. **1.8.19 — последняя версия старой IDE 1.x.** Дальше Arduino ушёл на IDE 2.x
   с другим редактором и другим менеджером плат.
2. **Ядро `arduino-esp32` версии 3.x требует Arduino IDE 2.x.** На 1.8.19
   официально доступны версии ядра только до **2.0.17** включительно.
3. И это, как правило, **плюс**, а не проблема: практически все готовые скетчи
   для ESP32-CAM-машинок (примеры продавцов, статьи, YouTube-проекты) писались
   под ядро **1.0.x — 2.0.x**. На ядре 3.x они массово не собираются, потому что
   там сменился API:
   - `ledcSetup()` + `ledcAttachPin()` → `ledcAttach()` (ШИМ моторов),
   - переехали части структур камеры и заголовков,
   - изменилось поведение `analogWrite`, таймеров, `Serial`.

То есть 1.8.19 — это способ остаться на ядре 2.0.x, под которое написан весь
существующий код для этих роботов.

## Что рекомендую

**Вариант А (проще, меньше сюрпризов):** остаться на Arduino 1.8.19 + ядро
**esp32 2.0.17**. Весь код из этого репозитория соберётся, и сторонние примеры
для машинок тоже.

**Вариант Б:** Arduino IDE 2.x + ядро esp32 3.x. Код в `sketches/` написан с
`#if ESP_ARDUINO_VERSION_MAJOR >= 3` и соберётся на обоих ядрах, но сторонние
примеры с ядром 3.x чаще ломаются.

Смешивать не надо: выберите одно и не трогайте, пока робот не заработает.

## Установка ядра ESP32

`File → Preferences → Additional Boards Manager URLs`:

```
https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
```

Затем `Tools → Board → Boards Manager` → найти **esp32 by Espressif Systems** →
в списке версий выбрать **2.0.17** (не «latest», если вы на 1.8.19) → Install.

Ставится долго, качается около 200 МБ тулчейна — это нормально.

## Настройки платы (AI-Thinker ESP32-CAM)

| Пункт в Tools | Значение | Зачем |
|---|---|---|
| Board | `AI Thinker ESP32-CAM` | правильные пины камеры и раскладка флеша |
| Partition Scheme | `Huge APP (3MB No OTA/1MB SPIFFS)` | **обязательно**, иначе `Sketch too big` |
| PSRAM | `Enabled` | без неё кадры больше QVGA не влезают |
| CPU Frequency | `240MHz (WiFi/BT)` | |
| Flash Frequency | `80MHz` | |
| Flash Mode | `QIO` | |
| Upload Speed | `115200` | если срывается — понизить до `57600` |
| Core Debug Level | `None` (для отладки — `Info`) | |

`Partition Scheme` — самая частая забытая настройка. Симптом: `text section
exceeds available space in board` при компиляции.

## Схема прошивки

У ESP32-CAM нет USB — нужен внешний USB-TTL (CH340 / CP2102 / FT232) или
плата-подложка **ESP32-CAM-MB** (с ней USB есть, и GPIO0 замыкается кнопкой
`BOOT`).

```
USB-TTL              ESP32-CAM
  5V  ------------->  5V         (НЕ на 3V3, если питаете с 5V)
  GND ------------->  GND
  TX  ------------->  U0R  (RX)
  RX  <-------------  U0T  (TX)
                      GPIO0 ---- GND   (перемычка только на время прошивки)
```

Перекрёст TX↔RX обязателен. Если перепутать — `Failed to connect to ESP32:
Timed out waiting for packet header`.

## Порядок заливки

1. Замкнуть `GPIO0` на `GND`.
2. Подать питание или нажать `RESET`.
3. `Upload` в IDE. В логе появится `Connecting........_____`, потом `Writing at ...`.
4. Дождаться `Hard resetting via RTS pin...`.
5. **Снять перемычку GPIO0.**
6. Нажать `RESET`.
7. Открыть Serial Monitor на **115200** и читать лог.

Если пропустить шаг 5, плата останется в загрузчике и программу не запустит —
в Serial будет висеть `waiting for download`. Снаружи это ровно то же, что
«робот не раздаёт Wi-Fi».

## Как читать лог загрузки

В Serial Monitor при старте всегда идёт строка загрузчика вида:

```
rst:0x1 (POWERON_RESET),boot:0x13 (SPI_FAST_FLASH_BOOT)
```

Что бывает вместо неё:

| Строка | Значение |
|---|---|
| `rst:0x1 (POWERON_RESET)` | нормальный старт с питания |
| `rst:0x3 (SW_RESET)` | программный сброс |
| `rst:0x10 (RTCWDT_RTC_RESET)` | watchdog — программа зависла |
| `Brownout detector was triggered` | просадка питания, **чините питание** |
| `rst:0x7 (TG0WDT_SYS_RESET)` | тайм-аут watchdog таймера |
| `waiting for download` | GPIO0 всё ещё на GND |
| `flash read err, 1000` | битая прошивка / плохой контакт флеша — перепрошить |

Если строка `rst:...` повторяется каждую секунду — это boot loop. Причины по
частоте: питание → GPIO12 подтянут в HIGH мотор-драйвером → битая прошивка.
