# ESP32-CAM 4WD Camera Robot Car

Прошивки и разбор настройки 4WD камера-робота на ESP32-CAM (AI-Thinker).

## Что это за робот

**Keyestudio KS5024, ESP32-CAM 4WD Monitoring Car.** Официальная документация:
[docs.keyestudio.com/projects/KS5024](https://docs.keyestudio.com/projects/KS5024/en/latest/docs/4WD%20Camera%20Robot%20Car.html),
исходники: [github.com/keyestudio/KS5024-...](https://github.com/keyestudio/KS5024-Keyestudio-ESP32-CAM-4WD-Monitoring-Car).

Штатная прошивка работает в режиме **STA**, а не AP: робот подключается к вашей
сети или к хотспоту телефона, и пульт открывается по IP, который роутер ему
выдал и который печатается в Serial Monitor. Адреса `192.168.4.1` у этого
робота в заводской комплектации **нет** — он бывает только в режиме точки
доступа, которого штатная прошивка не использует. Прошивка `03_car_ap_camera`
из этого репозитория добавляет режим AP как альтернативу: тогда роутер не нужен
совсем, что удобно вне дома.

Подтверждённые официальной документацией параметры:

| | |
|---|---|
| Драйвер моторов | L298N |
| Левая сторона | `GPIO 13` вперёд, `GPIO 12` назад |
| Правая сторона | `GPIO 15` вперёд, `GPIO 14` назад |
| Фара | `GPIO 4` |
| Камера | OV2640, раскладка AI-Thinker |
| Ядро esp32 | **2.0.12**, Keyestudio требует именно его |
| Ориентация картинки | `set_vflip(s, 1)` — камера на шасси перевёрнута |

Отдельно в документации (раздел 12.5): **без подключённой антенны прошивка
зальётся и Wi-Fi может даже подключиться, но страница управления по IP не
откроется.** Антенну нужно прикрутить до включения.

## TL;DR — что у вас сломалось

Скетч, который вы заливали, работает в режиме **station (WIFI_STA)** — это режим
*клиента*: плата ищет чужую сеть и подключается к ней. Точку доступа он **не
создаёт вообще**. А адрес `192.168.4.1` — это адрес ESP32 **только в режиме
softAP** (точка доступа). Отсюда и весь замкнутый круг:

1. Вы залили STA-скетч → он затёр заводскую прошивку робота, которая раздавала Wi-Fi.
2. Сеть `Car` исчезла, потому что раздавать её больше некому.
3. STA-скетч пытается подключиться к сети `Car` с паролем `test1234` — то есть
   **к собственной точке доступа робота**, которую он же и стёр. Плата не может
   подключиться к сети, которую раздаёт она сама. Это гарантированный `FAILED`
   со статусом `1` (`WL_NO_SSID_AVAIL`) или `6` (`WL_DISCONNECTED`).
4. Подключиться к роботу нельзя → остаётся только «вшить код действий», что вы и
   описали.

Нужен режим **AP**, а не **STA**. Дальше — по шагам.

## AP или STA — выбор режима

| | **AP (softAP)** | **STA (station)** |
|---|---|---|
| Кто раздаёт Wi-Fi | робот | роутер |
| Адрес управления | всегда `192.168.4.1` | IP выдаёт роутер (`192.168.0.x`…) |
| Нужен роутер | нет | да |
| Работает на улице / в поле | да | нет |
| Интернет на телефоне | пропадает, пока подключён | остаётся |

Для машинки нужен **AP**. STA имеет смысл, только если робот должен жить в
домашней сети (например, чтобы телефон одновременно был в интернете).

## Правильная цепочка действий

### 1. Прошить диагностический скетч

Начинайте с `sketches/01_ap_test` — без камеры и моторов. Он проверяет одну
вещь: плата загружается и поднимает точку доступа. Если не работает он, нет
смысла отлаживать камеру.

Настройки в Arduino IDE (подробнее — `docs/arduino-ide.md`):

- **Board:** `AI Thinker ESP32-CAM`
- **Partition Scheme:** `Huge APP (3MB No OTA/1MB SPIFFS)` ← без этого прошивка с камерой не влезет
- **PSRAM:** `Enabled`
- **Upload Speed:** `115200`

Прошивка ESP32-CAM (у платы нет USB, нужен USB-TTL адаптер):

```
USB-TTL        ESP32-CAM
5V     ------- 5V
GND    ------- GND
TX     ------- U0R   (RX)
RX     ------- U0T   (TX)   <-- перекрёстно!
               GPIO0 --- GND  (перемычка на время прошивки)
```

Порядок: замкнуть `GPIO0` на `GND` → подать питание / нажать `RESET` → `Upload`
→ дождаться `Hard resetting via RTS pin` → **снять перемычку GPIO0** → нажать
`RESET`. Пока GPIO0 на земле, плата остаётся в режиме загрузчика и вашу
программу **не запускает** — это одна из самых частых причин «ничего не
раздаёт».

### 2. Проверить по Serial Monitor

Открыть Serial Monitor на **115200**, нажать RESET. Должно быть:

```
=== AP test ===
reset reason: 1
softAP("Car"): OK
AP IP:  192.168.4.1
HTTP сервер запущен на порту 80
```

Если вместо этого сыплется `Brownout detector was triggered` или бесконечный
`rst:0x...` — это **питание**, см. шаг 3.

### 3. Питание — половина всех проблем

Камера + Wi-Fi + 4 мотора в пике берут больше 1 А. USB-TTL адаптер даёт
~100–500 мА. Этого не хватает, плата уходит в brownout-ребут по кругу, и снаружи
это выглядит как «не раздаёт Wi-Fi».

- Питание платы: отдельные **5 В, минимум 2 А** (повербанк или BEC/понижайка от аккумулятора).
- Мотор-драйвер питать **от аккумулятора напрямую**, не через 5 В-линию ESP32.
- **Земля общая** у платы и драйвера.
- Электролит **470–1000 мкФ** по питанию платы сильно помогает от просадок при старте моторов.
- Отлаживайте Wi-Fi/камеру **с вывешенными колёсами** или с отключённым питанием моторов.

### 4. Прошить рабочую прошивку

`sketches/03_car_ap_camera`. **Перед заливкой проверьте пины моторов** в начале
файла:

```cpp
#define PIN_L_IN1   12
#define PIN_L_IN2   13
#define PIN_R_IN1   14
#define PIN_R_IN2   15
```

Это самое частое расположение для ESP32-CAM-машинок (пины SD-карты, она не
нужна), но у разных китов разводка разная — сверьтесь с шелкографией на плате
или примером от продавца. Если робот не едет или едет не туда, правьте эти
четыре числа и полярность (`IN1`/`IN2` местами).

### 5. Подключиться и управлять

1. Отключить USB-TTL, дать нормальное питание.
2. На телефоне/ноутбуке: Wi-Fi → сеть **`Car`** → пароль **`test1234`**.
3. Телефон скажет «без доступа к интернету» — **это нормально**. Обязательно
   отключите автопереключение на мобильные данные (Android: «Адаптивный
   Wi-Fi» / «Переключаться на мобильную сеть», iOS: Wi-Fi Assist), иначе
   система молча отвалится от сети робота.
4. Отключить **VPN** и **Private DNS** — они ломают доступ к локальному IP.
5. В браузере набрать **`http://192.168.4.1`** — обязательно с `http://`,
   иначе браузер уйдёт в поисковик и/или попытается `https`, которого тут нет.
6. Видео отдаётся отдельным сервером: `http://192.168.4.1:81/stream`
   (страница подставляет его в `<img>` сама).

Управление: стрелки на странице (удерживать — едет, отпустить — стоп), ползунок
скорости, кнопка фары, на компьютере — стрелки клавиатуры.

## Почему видео на отдельном порту

MJPEG-стрим занимает рабочий поток HTTP-сервера целиком и надолго. Если
повесить стрим и команды управления на один сервер, кнопки начнут отвечать
через несколько секунд или зависать совсем. Поэтому в прошивке два экземпляра
`httpd`: порт **80** — пульт и команды, порт **81** — только видео. Так делает
и штатный пример `CameraWebServer` от Espressif.

## Безопасность движения

В прошивке есть **failsafe**: если команд не было 2 секунды (закрыли страницу,
телефон отвалился, ушли из зоны), моторы останавливаются. Веб-пульт держит
робота в движении только пока кнопка нажата. Без этого робот уезжает в стену
при первом же обрыве связи.

## Ограничения этой прошивки

- Точка доступа с фиксированным паролем — годится для игрушки, не для чего-то
  ответственного. Управление без авторизации: кто подключился к `Car`, тот и рулит.
- Одновременный просмотр видео больше чем с одного устройства ESP32-CAM
  практически не вывозит.
- Код **не скомпилирован** — в окружении, где он писался, нет Arduino-тулчейна.
  Проверена структура и совместимость API, но первую сборку надо сделать у себя.
